# 買い物アプリ 要件定義と設計

- 作成日：2026/11/15
- 状態：ユーザーの確認待ち
- 次の工程：`docs/実装計画.md` に沿って実装する

## 1. 目的

- 夫婦2人の買い物で、「どの店で何を買うと安いか」を記憶に頼らず分かるようにする
- 買い物リストを2人で共有し、店ごとにまとめて買い物しやすくする
- 曜日で決まるセールを見落とさないようにする

## 2. 使う人と役割

- 夫：店・商品・値段の登録と更新、設定
- 妻：買い物リストへの追加、買い物中のチェック
- 役割で画面や権限は分けない。2人とも全画面を使える

## 3. 使う環境と費用

- Web アプリ。iPhone のホーム画面にアイコンを追加して使う
- 端末：iPhone 12 mini、iPhone 13。パソコンのブラウザでも同じ画面を開ける（優先度低）
- 費用：0円。無料枠だけで動かす
- 2台とパソコンは同じデータを見る

## 4. 今回作るもの

### 4.1 商品

- 粒度は「牛乳」「牛こま」「牛ロースかたまり」。メーカー・容量は持たない
- 商品ごとに持つもの
  - 名前
  - 値段の単位：1つあたり／100gあたり
  - 税率：食品（8%）／食品以外（10%）
- 最初から入っている商品を100個ほど用意する（食品と日用品。単位と税率は設定済み）
- 商品は追加・編集・削除できる
- 買い物リストの画面から新しい商品を足すときは名前だけ入れる。単位は「1つあたり」、税率は「食品」で作り、あとでデータ一覧から直せる

### 4.2 店

- 店ごとに持つもの
  - 名前
  - 優先順（設定で並べ替える）
  - 提案での扱い：ふだん行く／ふだん行かない／常に外す
  - 前回の入力が税込か税抜か（次の入力の初期値に使う）

### 4.3 値段

- 店 × 商品ごとに、通常の値段を1つ持つ
- 曜日セールの値段を別に持つ。1つの店 × 商品に、複数の曜日を登録できる
  - 例：A店・卵・火曜・98円
- 入力のたびに税込か税抜かを選ぶ。初期値はその店の前回の選択
- 表示と比較は、すべて税込にそろえる
  - 税抜からの計算：税抜 ×（1 ＋ 税率）。1円未満は切り捨てる
- 値段ごとに更新日を持ち、一覧に出す

### 4.4 買い物リスト

- 2人で1つのリストを共有する
- 足し方
  - 検索欄を押すと「よく買うもの」が、買った回数の多い順に並ぶ。押すとリストに入る
  - 文字を打つと商品名で絞り込む
  - 見つからない商品は、その場で新しく追加できる
- 同じ商品は、リストに1つだけ入る
- 商品ごとにメモを書ける（例：300g）。数量の欄は持たない
- チェックした商品は、リストの下の「買ったもの」に移る。もう一度押すと戻る
- 「買ったもの」は、日付が変わると画面から消える。記録は残す
- 片方の操作は、もう片方の画面に数秒で出る

### 4.5 店の提案

買い物リストの画面を「提案」モードに切り替えると出る。

- 対象の期間：今日から7日間
- 対象の日：その期間のうち、設定の「行ける曜日」に当たる日
- 対象の店：扱いが「ふだん行く」の店
- 選び方（商品ごと）
  1. 対象の日 × 対象の店の中で、税込の値段が一番安い組み合わせを選ぶ
     - その曜日にセールがあればセールの値段、なければ通常の値段を使う
  2. 同じ値段なら、近い日を選ぶ
  3. それも同じなら、優先順が上の店を選ぶ
- 見せ方
  - 日ごと、その中で店ごとに、商品をまとめて出す
  - 対象の店のどこにも値段がない商品は「店が未定」にまとめる
- その週だけの切り替え
  - 日：画面の上に行ける日が並ぶ。押すとその日を外せる。日付ごとに覚え、過ぎたら消える
  - 店：画面の上に店が並ぶ。押すと行く・行かないを切り替えられる。切り替えてから7日たつと、設定の値に戻る
  - 切り替えるたびに、残りの日と店で選び直す
  - 切り替えた内容は2人で共有する
- 差額の表示
  - 商品ごとに、その店を外した場合の次の候補と差額を出す
    - 例：「外すと A店 238円（+40円）」
  - セールを待って後ろの日に回した商品には、その日を外した場合の候補と差額を出す
    - 例：「水曜を外すと 今日 A店 198円（+100円）」
- ふだん行かない店のほうが安いとき
  - 商品の横に一言出す。例：「B店なら 168円（−30円）」
  - 押すと、その商品だけをその店に回せる。リストから消えるまで有効
- 「常に外す」の店は、提案にも一言にも出さない
- 提案モードでも、チェックと値段の修正ができる

### 4.6 データ一覧

- 1行が「店 × 商品」の値段。通常の値段・曜日セール・更新日を出す
- 絞り込み：店と商品。商品は入れなくてもよい
  - すべての店で商品名を入れると、当てはまる商品を、登録している店ごとに並べる。値段のない店も出す（2026/11/16 追加）
- 行を押すと編集できる
- 「＋」から、値段・商品・店を追加できる
- 続けて入力
  - 店で絞り込むと、その店にまだ値段がない商品も並ぶ
  - 値段の欄を上から順に打てる。1つ確定すると次の商品に進む

### 4.7 通知

> 2026/11/19 保留。今のセールは自分で入れた固定の値段で、知らせてもリマインダーにしかならないため。チラシ連携（6章）と一緒に作る

- 設定した時刻に、次の3つがそろった日だけ届く
  - 今日が「行ける曜日」である
  - 今日が、どこかの店の曜日セールの日である（「常に外す」の店は除く）
  - そのセールの商品が、買い物リストに未チェックで入っている
- 内容の例：「今日のセール（リストにあり） A店：卵 98円」
- 押すと、提案モードが開く
- 当てはまる商品がない日は届かない
- 通知のオン・オフと時刻は、iPhone ごとに決める
- 行けない曜日には届かない。あとから変えられる作りにしておく

### 4.8 ダッシュボード（優先度低。最後に作る）

- よく買う商品：買った回数の多い順
- よく行く店：買った回数の多い順
- 期間の切り替え：今月／3か月／全期間
- 元になる記録：チェックした日時・商品・店
  - 店は、チェックした時点で提案が割り当てていた店。未定のときは空にする
- 出すのは回数まで。金額は出さない

### 4.9 設定

右上の歯車から開く。

- 2人で共有するもの
  - 買い物に行ける曜日（初期値：水・金・土・日）
  - 店の優先順
  - 店ごとの扱い：ふだん行く／ふだん行かない／常に外す
- iPhone ごとのもの
  - 通知のオン・オフ
  - 通知の時刻（初期値：8:00）
- データの書き出し（控えを手元に残す）

### 4.10 ログイン

- 1人ずつ、メールアドレスとパスワードで入る
- アカウントは2人分だけを最初に作る。新規登録の画面は作らない
- 一度入った端末は、入ったままにする
- 誰が足したか・誰がチェックしたかを記録する

### 4.11 電波が弱いとき

- 電波がなくても、リスト・提案・データ一覧を見られる
- 電波がなくても、追加・チェック・メモ・値段の修正ができる
- 電波がない間の操作は端末にためておき、戻ったら自動で反映する
- 2人の操作が食い違ったときは、項目ごとに、あとから行った操作を優先する
- 反映待ちの操作があるときは、画面に小さく出す

## 5. 画面の構成

- メニュー：リスト／ダッシュボード／データ
  - iPhone では画面の下に常に出す
  - パソコンでは画面の上に横並びで出す
- 右上に歯車（設定）
- 最初に開く画面はリスト

| 画面 | 内容 |
| --- | --- |
| リスト | 買い物リスト。上の切り替えで「リスト」と「提案」の2つのモードを行き来する |
| ダッシュボード | よく買う商品・よく行く店 |
| データ | 店 × 商品の値段の一覧。登録と編集 |
| 設定 | 行ける曜日・店の優先順と扱い・通知 |
| ログイン | メールアドレスとパスワード |

## 7. 仕組み

### 7.1 使うサービス

| 役目 | サービス | 備考 |
| --- | --- | --- |
| ログイン | Supabase | メールアドレスとパスワード。新規登録は止める |
| データ | Supabase | 2人の画面への即時の反映も Supabase の機能を使う |
| 毎朝のタイマーと通知の送信 | Supabase | 決まった間隔で動き、時刻になった iPhone に送る |
| 画面の置き場 | GitHub | 画面のファイルを置くだけ。プログラムの保管場所も兼ねる |

- GitHub の無料プランでは、プログラムを公開の状態にして置く。公開されるのはプログラムだけで、買い物リスト・値段・店の名前・メールアドレス・パスワードは含まれない
- 非公開にしたくなったら、置き場を Cloudflare に移せる
- Supabase の無料プランは、1週間ほとんど使われないと一時停止する。管理画面のボタンで再開でき、データは残る
- 止まると通知とデータの反映が止まる。端末にためた分は、再開後に反映される

### 7.2 作り方の方針

- 画面：TypeScript と React で作り、ホーム画面に追加できる形（PWA）にする
- 端末の中にデータの写しを持つ。画面は写しを見て動き、裏で Supabase とそろえる
  - これで、電波がなくても見る・操作するができる
- 提案の選び方・税の計算・通知の条件は、画面から切り離した部品にする。単体で確かめられるようにするため
- 時刻と曜日は、日本時間で判断する

### 7.3 持つデータ

| 名前 | 中身 |
| --- | --- |
| 店 | 名前、優先順、扱い、前回の税込・税抜 |
| 商品 | 名前、単位、税率、最初から入っているものかどうか |
| 値段 | 店、商品、通常の値段、税込・税抜、更新日 |
| 曜日セール | 店、商品、曜日、値段、税込・税抜 |
| リストの商品 | 商品、メモ、足した人と日時、チェックした人と日時、買った店、回す店の指定 |
| その週の切り替え | 外した日、店の行く・行かないの切り替えと期限 |
| 共有の設定 | 行ける曜日 |
| 通知の宛先 | 利用者、端末の宛先、オン・オフ、時刻、最後に送った日 |

- ログインした2人だけが読み書きできるようにする

## 8. 確かめ方

- 自動で確かめるもの
  - 提案の選び方（安い順・同額のときの決め方・日や店を外したとき・店が未定・差額）
  - 税の計算（税込・税抜、8%・10%、切り捨て）
  - 通知の条件（届く日・届かない日）
  - 電波がない間の操作の反映と、食い違いの扱い
- 実機で確かめるもの
  - iPhone 2台でホーム画面に追加し、ログインできる
  - 片方の操作が、もう片方に出る
  - 通知が、設定した時刻に届く
  - 機内モードで操作し、戻したときに反映される

## 9. 始める前に要るもの

- Supabase のアカウント（無料）
- GitHub のアカウント（すでにある）
- 2人分のメールアドレス（ログイン用）

- 無料枠の上限（確かめた）

  - 2人の使い方では、どれも上限の1%未満に収まる見込み（推測）
- Supabase の決まり（確かめた）
