## 1. 目的と全体像

**目的**：夫婦2人が iPhone 2台で使う買い物アプリを、0円で動く Web アプリ（PWA）として作る。

**仕組み**
- 画面は Vite＋React＋TypeScript の静的ファイル。GitHub Pages に置く
- データとログインは Supabase（Postgres・Auth・Realtime）
- 端末の中に IndexedDB の写しを持つ。画面は写しだけを読み書きし、同期の部品が裏で Supabase とそろえる
- 毎朝の通知は、Supabase の pg_cron が15分おきに Edge Function を呼び、Web Push で送る

**使う技術**
- 画面：Vite、React、TypeScript、React Router（HashRouter）、素の CSS
- 端末の中のデータ：Dexie、dexie-react-hooks
- サーバー：@supabase/supabase-js、Supabase CLI、Edge Functions（Deno）、pg_cron、pg_net、Vault
- PWA：vite-plugin-pwa（injectManifest。自前の service worker）
- 通知の送信：`jsr:@negrel/webpush`
- テスト：Vitest、fake-indexeddb、@testing-library/react

## 2. 全体の決まり

- 費用は 0円。有料のプラン・サービス・ライブラリを使わない
- 対象の端末：iPhone 12 mini と iPhone 13 の Safari（iOS 16.4 以降）、パソコンのブラウザ。幅 360px から崩れない
- 時刻と曜日は日本時間で判断する。曜日は 0＝日曜 〜 6＝土曜
- 値段は円の整数。表示と比較は税込。税抜からは `floor(税抜 × (100 ＋ 税率) / 100)`
- リポジトリは公開。次のものを入れない
  - 秘密の鍵（Supabase の secret key、VAPID の秘密鍵、DB のパスワード）
  - 個人の情報（メールアドレス、実際の店の名前、パソコンのユーザー名を含むパス）
- Supabase の URL と publishable key は公開してよい（RLS で守る）
- `src/domain/` は純粋な関数だけ。React・Dexie・Supabase・npm のライブラリを import しない。import は拡張子 `.ts` まで書く（Deno でも同じファイルを使うため）
- データの行は、端末の中もサーバーも同じ列名（snake_case）で持つ。変換の層を作らない
- 行は消さない。`deleted_at` に日時を入れて消したことにする
- 画面の言葉は日本語。要件定義の言葉をそのまま使う（リスト／提案／データ／ダッシュボード／設定、ふだん行く／ふだん行かない／常に外す、店が未定、買ったもの）
- 新規登録の画面は作らない

## 4. データの形と、部品の約束

### 4.1 サーバーの表

同期する表には、共通の列を付ける。

```sql
field_times        jsonb       not null default '{}',   -- 列名 → その列を最後に変えた操作の時刻（ISO）
deleted_at         timestamptz,
server_updated_at  timestamptz not null default now()   -- トリガーが insert / update のたびに now() を入れる
```

| 表 | 列（共通の列を除く） |
| --- | --- |
| `stores` | `id uuid pk`、`name text`、`sort_order int`（小さいほど優先）、`visit_mode text`（`usual`／`other`／`never`）、`default_tax_mode text`（`included`／`excluded`） |
| `products` | `id uuid pk`、`name text`、`unit text`（`piece`／`100g`）、`tax_rate int`（8／10）、`is_preset boolean` |
| `prices` | `id uuid pk`、`store_id`、`product_id`、`amount int`、`tax_mode text`、`price_updated_at timestamptz`。`unique(store_id, product_id)` |
| `sale_prices` | `id uuid pk`、`store_id`、`product_id`、`weekday smallint`（0〜6）、`amount int`、`tax_mode text`。`unique(store_id, product_id, weekday)` |
| `list_items` | `id uuid pk`、`product_id`、`memo text default ''`、`added_by uuid`、`added_at timestamptz`、`checked_at timestamptz`、`checked_by uuid`、`bought_store_id uuid`、`forced_store_id uuid` |
| `excluded_dates` | `id uuid pk`、`date date unique`（提案で外した日） |
| `store_overrides` | `id uuid pk`、`store_id uuid unique`、`going boolean`、`expires_at timestamptz`（その週だけの行く・行かない） |
| `settings` | `id uuid pk`（1行だけ。固定の id）、`available_weekdays jsonb`（初期値 `[3,5,6,0]`） |

同期しない表（その端末だけのもの。電波があるときに直接読み書きする）

| 表 | 列 |
| --- | --- |
| `push_subscriptions` | `id uuid pk`、`user_id uuid default auth.uid()`、`endpoint text unique`、`p256dh text`、`auth text`、`enabled boolean`、`notify_time text`（`HH:MM`。15分きざみ）、`last_sent_on date` |

- id の決め方（`src/domain/ids.ts`）
  - `prices`：`uuidv5(store_id + ':' + product_id)`
  - `sale_prices`：`uuidv5(store_id + ':' + product_id + ':' + weekday)`
  - `excluded_dates`：`uuidv5('date:' + date)`
  - `store_overrides`：`uuidv5('override:' + store_id)`
  - 最初から入っている商品：`uuidv5('preset:' + name)`
  - ほかは `crypto.randomUUID()`
  - 2台が電波なしで同じものを作っても、同じ id になって1行にまとまるようにするため。uuidv5 は Web Crypto の SHA-1 で自前で書く
  - uuidv5 の名前空間は、このアプリ用の固定の uuid を1つ作り、`ids.ts` に定数で持つ。一度決めたら変えない
- RLS と許可
  - 同期する表：`authenticated` に `select, insert, update` を許可。方針は `using (true) with check (true)`（ログインできるのは2人だけのため）
  - `push_subscriptions`：`authenticated` に `select, insert, update, delete`。方針は `user_id = auth.uid()`
  - `anon` には何も許可しない
  - 許可（`grant`）を表ごとに明示する。書かないとアプリから見えない
- 同期する表を全部、`supabase_realtime` の publication に入れる

### 4.3 純粋な関数（`src/domain/`）

```ts
// dates.ts — 日本時間。日付は 'YYYY-MM-DD' の文字列で持つ
export function jstDate(now: Date): string;
export function jstTime(now: Date): string;            // 'HH:MM'
export function weekdayOf(date: string): number;       // 0=日
export function addDays(date: string, n: number): string;

// tax.ts
export function toTaxIncluded(amount: number, mode: TaxMode, taxRate: number): number;

// list.ts
export function activeItems(items: ListItem[], today: string): { toBuy: ListItem[]; boughtToday: ListItem[] };
export function duplicatesToRemove(items: ListItem[]): string[];   // 同じ商品の未チェックが複数あるとき、added_at が古い1つを残し、ほかの id を返す
export function frequentProducts(items: ListItem[], products: Product[]): { product: Product; count: number }[];
export function searchProducts(products: Product[], query: string): Product[];

// plan.ts
export type Candidate = { date: string; store_id: string; price: number; is_sale: boolean };
export type Alt = Candidate & { diff: number };
export type PlannedItem = {
  item: ListItem; product: Product;
  chosen: Candidate | null;
  alt_if_store_excluded: Alt | null;   // 選ばれた店を外したときの次の候補（diff >= 0）
  alt_if_date_excluded: Alt | null;    // 選ばれた日を外したときの次の候補（diff >= 0）
  cheaper_elsewhere: Alt | null;       // 行かない店のほうが安いとき（diff < 0）。chosen が null のときは diff = 0 で候補を入れる
};
export type Plan = {
  dates: string[];                     // 対象の日
  going_store_ids: string[];
  groups: { date: string; stores: { store_id: string; items: PlannedItem[] }[] }[];
  undecided: PlannedItem[];
};
export type PlanInput = {
  today: string; now: string;          // now は ISO。store_overrides の期限の判定に使う
  available_weekdays: number[];
  excluded_dates: string[];
  stores: Store[]; store_overrides: StoreOverride[];
  products: Product[]; prices: Price[]; sale_prices: SalePrice[];
  items: ListItem[];                   // 未チェックで、消されていないもの
};
export function buildPlan(input: PlanInput): Plan;

// notification.ts
export type SaleHit = { store_id: string; store_name: string; product_name: string; price: number; unit: Unit };
export function saleHitsForToday(input: {
  today: string; available_weekdays: number[];
  stores: Store[]; products: Product[]; prices: Price[]; sale_prices: SalePrice[]; items: ListItem[];
}): SaleHit[];                          // 行けない曜日なら空
export function notificationText(hits: SaleHit[]): { title: string; body: string };
export function isDue(sub: { enabled: boolean; notify_time: string; last_sent_on: string | null }, today: string, nowTime: string): boolean;

// dashboard.ts
export type Period = 'this_month' | 'three_months' | 'all';
export function purchaseCounts(input: { items: ListItem[]; products: Product[]; stores: Store[]; period: Period; today: string }):
  { byProduct: { name: string; count: number }[]; byStore: { name: string; count: number }[] };
```

**`buildPlan` の決まり**
1. 対象の日 D：今日から7日間のうち、`available_weekdays` に当たり、`excluded_dates` にない日
2. 行く店 G：`visit_mode` が `never` でなく、消されていない店のうち
   - 期限内（`expires_at > now`）の `store_overrides` があれば、その `going`
   - なければ `visit_mode === 'usual'`
3. 値段：その店 × 商品の通常の値段がある場合だけ候補になる。その曜日のセールがあれば `min(通常, セール)` を使う。どちらも税込にしてから比べる
4. 選び方：D × G の候補から、値段が安い → 日が近い → `sort_order` が小さい、の順で1つ選ぶ
5. `forced_store_id` がある商品：その店（`never` でなく、値段がある）に限って 4 を行う。値段がなければ、指定がないものとして扱う。この店は G になくても `groups` に出す
6. `alt_if_store_excluded`：選ばれた店以外の候補で 4 を行った結果
7. `alt_if_date_excluded`：選ばれた日以外の候補で 4 を行った結果
8. `cheaper_elsewhere`：`never` でなく G にない店の候補で 4 を行い、選ばれた値段より安いときだけ入れる。`chosen` が null なら、候補があれば入れる
9. `groups` は日が近い順、その中で `sort_order` が小さい順。商品は `added_at` の順
10. D が空、または候補がない商品は `undecided`

### 4.4 同期の部品（`src/data/`）

```ts
// remote.ts — テストで偽物に差し替えられるようにする
export interface Remote {
  fetchRow(table: SyncTable, id: string): Promise<Record<string, unknown> | null>;
  insertRow(table: SyncTable, row: Record<string, unknown>): Promise<'inserted' | 'conflict'>;
  updateRow(table: SyncTable, id: string, patch: Record<string, unknown>): Promise<void>;
  fetchSince(table: SyncTable, cursor: string | null): Promise<Record<string, unknown>[]>;  // server_updated_at >= cursor
}

// sync/mutate.ts — 画面が使う書き込み口は、この3つだけ
export function createRow<T extends SyncTable>(table: T, row: RowOf<T>): Promise<void>;
export function patchRow<T extends SyncTable>(table: T, id: string, patch: Partial<RowOf<T>>): Promise<void>;
export function softDelete(table: SyncTable, id: string): Promise<void>;

// sync/resolve.ts
export function resolvePatch(serverFieldTimes: Record<string, string>, patch: Record<string, unknown>, opTime: string):
  { accepted: Record<string, unknown>; fieldTimes: Record<string, string> };

// sync/engine.ts
export function startSync(remote: Remote): () => void;      // 止める関数を返す
export function useSyncStatus(): { pending: number; failed: number; online: boolean };
```

**決まり**
- Dexie の表：サーバーと同じ8つの表（主キー `id`）、`outbox`（`++seq`。`table`・`row_id`・`kind`（`create`／`patch`）・`patch`・`op_time`・`attempts`・`last_error`）、`meta`（表ごとの読み込み済みの位置）
- 書き込み：1つの Dexie のトランザクションで、写しの行を直し（変えた列の `field_times` に `op_time` を入れる）、`outbox` に1件足す。画面はすぐ変わる
- push：`outbox` を `seq` の順に1件ずつ送る
  - `create`：サーバーに行がなければ insert。あれば（または insert がぶつかれば）全部の列を `patch` として扱う
  - `patch`：サーバーの行の `field_times` を読み、`resolvePatch` で通った列だけを update する。`field_times` も合わせて書く
  - `resolvePatch`：列ごとに、`opTime >= サーバーの時刻`（なければ通す）なら通す
  - 通信の失敗：そこで止め、`outbox` を残す。あとでやり直す
  - それ以外の失敗（4xx）：`attempts` と `last_error` を書いて飛ばす。3回失敗したら「反映できなかった操作」として数える
- pull：表ごとに `fetchSince` で読み、写しに入れる。入れる前に、その行に対する未送信の `outbox` の `patch` を `seq` の順に上から当て直す（未送信の操作が、古いサーバーの値で消えないようにする）
- realtime：`postgres_changes` を受けたら、その行を pull と同じ手順で写しに入れる
- 動くタイミング：起動時、ログイン直後、`online` イベント、画面が前面に戻ったとき、書き込みの直後、前面にある間は60秒ごと
- ログイン情報は端末に残す。電波がなくても、残っていればログイン済みとして画面を出す
